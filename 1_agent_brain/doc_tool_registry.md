

# 🔌 Internal Documentation: `tool_registry.py`

## Overview
The `tool_registry.py` file is the critical bridge layer of the DataIntelEngine. It acts as the "Switchboard" connecting the AI Orchestrator (`main_orchestrator.py`) to the statistical engines (`2_core_libraries`). 

The AI does not know how to import Python modules, run R scripts, or save files. It only knows how to output JSON text. The `tool_registry.py` translates that JSON text into safe, executable commands, runs the heavy biometric math, and returns a human-readable text summary back to the AI.

---

## 🏗️ Architecture & Component Breakdown

### 1. Folder Routing (The Monorepo Backbone)
Because we use a strict monorepo structure, the agent's brain cannot naturally "see" the math libraries. 
* **`sys.path.append`:** This file explicitly injects the `2_core_libraries/python_core` folder into Python's system path at runtime. This allows us to securely import functions like `tetraploidMLPred` without moving files or corrupting the directory structure.
* **Workspace Management:** It globally defines the `WORKSPACE_OUT` directory (`4_workspace/agent_outputs`). All tools must save their generated CSVs and `.png` plots here to keep the engine organized.

### 2. The Python Tool Wrappers
When the AI wants to run a Python tool, it calls a wrapper function in this file.
* **Type Conversion:** The wrappers handle formatting quirks from the LLM. For example, in `run_sim_multistage_field`, the LLM passes a raw JSON string for the `batch_years` parameter. The wrapper safely decodes this into a native Python dictionary before passing it to the core library.
* **Error Catching:** Every wrapper uses a `try/except` block. If the core math fails (e.g., pandas fails to find a column), the wrapper catches the Python `Exception`, converts it to a string, and returns it to the AI.

### 3. The Headless R Wrappers (`Rscript -e`)
This file allows the Python-based AI to execute complex R scripts natively and headlessly (without a GUI).
* **Dynamic Scripting:** Instead of maintaining separate `.R` bridge files, the Python wrappers dynamically write R code as a multi-line string.
* **Execution:** It uses Python's `subprocess` library to run `Rscript -e [command]`. 
* **The "Headless Plot" Trick:** For visual tools like the Diallel Analysis or GGE Biplot, the wrapper forces R to generate the `ggplot` objects in memory and immediately export them via `ggsave()` directly to the `WORKSPACE_OUT` directory.
* **Standard Output Capture:** The wrapper captures everything R prints to the console (`cat()` or `print()`) and returns that exact text back to the LLM.

### 4. The Master Dictionary (`AVAILABLE_TOOLS`)
This is the most important variable in the file. It is a simple Python dictionary that maps the string names generated by the AI to the actual wrapper functions. 
* **Rule:** The string keys in this dictionary (e.g., `'generate_gge_biplot'`) **MUST EXACTLY MATCH** the `"name"` fields defined in `tools_schema.json`. If they do not match, the orchestrator will fail to find the tool.

## 🔄 The Data Flow Lifecycle (Example: GGE Biplot)

1. **Input:** The orchestrator passes arguments to the registry: `dataset_path="wheat.csv"`, `gen_col="Names"`, `scaling=0.5`.
2. **Translation:** The registry injects those variables into a raw R string.
3. **Execution:** The registry spawns a background R process.
4. **Artifact Generation:** R performs the SVD math, draws the plot, and saves `gge_biplot.png` to the workspace.
5. **Output:** R prints: *"GGE Biplot Generated Successfully... Percentage Explained: 85%"*.
6. **Return:** The registry captures that text and returns it to `main_orchestrator.py`.

## ⚙️ Standard Operating Procedures (SOPs) for the Team

### Adding a New Tool to the Registry
When a Data Scientist writes a new biometric script and wants to give the AI access to it, follow these steps:

**If it is a Python Tool:**
1. Import the function at the top of `tool_registry.py`.
2. Write a `def run_your_tool(...)` wrapper that accepts explicit arguments, runs the function, saves any output to `WORKSPACE_OUT`, and returns a success string.
3. Wrap the execution in a `try/except Exception as e:` block.

**If it is an R Tool:**
1. Ensure the R function is compiled into our `DataIntelR` package (or exists as a standalone script).
2. Write a `def run_your_r_tool(...)` wrapper.
3. Construct the `r_command` string, ensuring you use `suppressPackageStartupMessages()` to prevent R from cluttering the AI's context window with loading warnings.
4. Use `subprocess.run` to execute it and capture the output.

**Final Step (CRITICAL):**
Add the new wrapper to the bottom of the file in the `AVAILABLE_TOOLS` dictionary. If you forget this step, the AI will know the tool exists (via the JSON schema) but will throw a "Tool not found in registry" error when it tries to use it.
