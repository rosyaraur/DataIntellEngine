# 💾 Internal Documentation: `4_workspace`

## Overview
The `4_workspace` directory serves as the **Dynamic Memory** of the DataIntelEngine. 

In a professional data science monorepo, code and data must never be mixed. This directory is the designated staging ground for all file-based inputs and outputs. It is the only place in the entire architecture where the AI Orchestrator (`1_agent_brain`) is permitted to read raw files and write generated artifacts.

**The Prime Directive:** This folder contains **transient data**. Do not store permanent source-of-truth databases here. This is a working directory where data is staged for immediate analysis and where the AI temporarily drops its results for the human user to review.

---

## 📂 Subfolder Breakdown

### 1. `raw_data/` (The Inbox)
This folder is the designated intake zone for all analyses.
* **Purpose:** To store the raw CSVs, Excel files, and genomic matrices that need to be processed by the core libraries.
* **How it gets populated:**
  * **Human Users:** A breeder or data scientist manually drags and drops a file (e.g., `hancock20_pheno.csv`) into this folder before asking the AI to analyze it.
  * **AI Database Connectors:** If you build an AI tool that queries an external SQL database (e.g., `query_breeding_database`), the AI's first step is to download that query result and save it here as a CSV, which it then feeds into the R/Python math tools.
* **AI Permissions:** strictly **Read-Only**. The AI Orchestrator is never allowed to modify or overwrite files in this directory to prevent accidental data destruction.

### 2. `agent_outputs/` (The Outbox)
This folder is the designated delivery zone for the AI.
* **Purpose:** To store all artifacts generated by the `2_core_libraries` during an AI-driven or UI-driven execution loop.
* **Expected Files:**
  * `.png` or `.pdf` plots (e.g., `gge_biplot.png`, `diallel_plot.png`).
  * `.csv` output files (e.g., `simulated_field_data.csv`, `spatial_blups_results.csv`).
* **AI Permissions:** **Read/Write**. The `tool_registry.py` script actively manages this folder, creating it automatically if it doesn't exist (`os.makedirs(WORKSPACE_OUT, exist_ok=True)`) and overwriting files with the same name during iterative testing.

## 🔄 The Data Flow Lifecycle

When the Lead Data Scientist issues a prompt to the AI, here is how the workspace is utilized:

1. **The Prompt:** *"Run a complete diallel analysis on the dataset at `4_workspace/raw_data/crosses_2026.csv`."*
2. **The Read:** The AI orchestrator passes that file path to the `tool_registry.py`. The registry feeds the path to the R script.
3. **The Processing:** R reads the CSV from `raw_data/` without modifying it.
4. **The Write:** R completes the math and uses `ggsave()` to explicitly force the output image into `4_workspace/agent_outputs/diallel_plot.png`.
5. **The Handoff:** The AI replies to the user: *"Analysis complete. The plot has been saved to your workspace outputs."* The human user can now open that image or drag it into a PowerPoint presentation.

## ⚙️ Standard Operating Procedures (SOPs) for the Team

### 1. Version Control (The `.gitignore` Rule)
**CRITICAL:** Genomic data and simulated field datasets can reach gigabytes in size. Pushing this folder to GitHub/GitLab will instantly crash your repository.
* Ensure that the `.gitignore` file at the root of the `DataIntelEngine` project includes the following lines:
  ```text
  # Ignore Workspace Data
  4_workspace/raw_data/*.csv
  4_workspace/raw_data/*.xlsx
  4_workspace/agent_outputs/*
  
  # Keep the folders themselves in Git, but ignore their contents
  !4_workspace/raw_data/.gitkeep
  !4_workspace/agent_outputs/.gitkeep
  ```

### 2. File Naming Conventions
When asking the AI to save files, use descriptive names to prevent overwriting previous analyses.
* **Bad Prompt:** *"Save the simulated data to the workspace."* (The tool registry will default to `simulated_field_data.csv`, overwriting whatever was there before).
* **Good Prompt:** *"Simulate the multi-stage field data and save the output as `2026_corn_simulation_v1.csv`."* *(Note: To support this, you may need to add a `save_name` parameter to your JSON schema and tool registry!)*

### 3. Workspace Cleanup
Because `agent_outputs/` is a dumping ground for iterative AI tests, it will fill up quickly. 
* **Recommendation:** Treat `agent_outputs/` like a Downloads folder. If an analysis produces a valuable plot or a final dataset that you want to keep for a long-term research paper, manually move that file out of the workspace and into a permanent project folder or cloud storage drive. 
* Periodically clear out the `agent_outputs/` folder to reclaim hard drive space on your PC.
